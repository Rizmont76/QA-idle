# 27 — Connected Late Frontiers

Authorized continuation of the active core-loop redesign, 2026-10-12.
Dependencies: 02, 05, 07, 10, 11, 20–26. Extends rack and network behavior without
changing earlier unlocks, prices or owned progress. Player feedback on the opening
remains pending; do not use this work as evidence of subjective enjoyment.

## A network that works for the studio

After buying at least one level of the existing Bridge protocol, the player can
connect Agents to studio testing through one free, explicit action. Existing and
new networks start disconnected. Show the connection only when Bridge is owned;
the Bridge card explains the capability before purchase once protocols are visible.

Connected Agents both generate computations and find bugs. Each computation's
worth of Agent work also runs a batch finding 100 bugs before shared production
bonuses. This candidate gives the late fleet a visible contribution alongside
thousands of retained individual autotests. Apply
the same upgrades, rank, experience, badges, research and rack multiplier as main
compiled tests. The current contribution is computationRate * agentPower.
Higher generators create immediately productive Agents, so the new layer changes
growth from an additive purchase ladder to a self-growing production chain.
No new currency or three-stage job is introduced. Main compiled tests and licensed
income retain their existing meaning; Agent work does not count as main releases
or as licensed installed autotest work.

The connection persists through network reboots and career prestige. Network
reboots reset live Agents, so their current bug production falls to the one-Agent
seed, while permanent compiled autotests keep working. Show the production and
income before/after the reset in the confirmation. A reboot trades current network
fleet output for permanent acceleration; it is never automatic.

## Continuous work and limits

Integrate connected Agent work from the analytic generator-chain integral, rather
than the starting or final Agent count. The network's resource balances being full
does not stop physical generators from doing work. Cap each generator tier at 1e15
at the moment it reaches that bound; integrate the remaining interval piecewise.
This fixes long/fine parity at tier saturation as well as connected production.

Keep total instantaneous bug production capped at 1e15. Ordinary crew and main
compiled tests have priority; Agents use the remaining room. Integrate until the
first combined rate-cap boundary, then use the capped rate. Licensed main test
work is calculated independently with its existing priority. Split at the engine's
badge, dispatcher and automation boundaries, and preserve existing offline
efficiency/time limits. Never retroactively activate a connection before its action.

Save network.linked as a boolean, default false. Accept true only for an eligible
network with a valid owned Bridge level. Missing old fields remain disconnected,
so old absence retains the old payout. No broad version reset or reinterpretation
of old resources is necessary. Preserve the flag explicitly in a network reboot.

## Rack configurations with visible consequences

After all four blueprints, offer three optional one-click layouts alongside manual
placement. They reuse unlocked modules and power rules; no automatic purchase or
extra gate. Applying a layout settles previous time, validates the full layout and
rebalances cores only when the existing autoBalance policy is enabled.

| Layout | Slots, row-major | Power | Purpose |
| --- | --- | ---: | --- |
| Flow | build, bus, verify / bus, deploy, bus | 9 | Grow test capital and Open-source insights faster |
| Production | build, manager, verify / manager, deploy, empty | 10 | Monetize current crew, tests and connected Agents |
| Projects | build, archive, verify / archive, deploy, empty | 10 | Complete harder certificates faster |

Cards preview actual bug production, sustainable pipeline throughput and project
work multiplier for the current career. A layout that exceeds available power
shows the required power and cannot be applied. Manual layouts remain supported;
the game does not force a layout or change it after a hire or prestige.

## Validation and delivery

Test tier-cap analytic growth vs fine advances, connected production vs direct
integrals, shared bug cap, licensed work priority, badge/dispatcher timing,
action settlement, opt-in connection, locked inertness, old saves and reboot losses.
Test layout eligibility, power validation, actual economic tradeoffs and save
round-trips. Measure the complete first path and late resets using validated actions.
Verify desktop/mobile presentation, reset previews and the real player save on a
separate test origin; run full checks and portable build before local delivery.
Keep the overall goal active until player validation and remaining release work
are actually complete.

Measured candidate: a validated normal first path reaches Director/prestige at
624 seconds, completes known blueprint configurations at 625 seconds, reboots
the network at 828/989 seconds and reaches Regions at 1164 seconds. The low-click
path reaches Regions at 1349 seconds. These are simulation results, not player
time promises or enjoyment validation. The connection and Production layout
then grow Agent output to half the studio's current non-network production in 149 seconds
after the third reboot, while retaining the earlier main autotests.
